# LLVM 与 MLIR 编译器工程研究生课程

[简体中文](graduate-course.md) | [English](graduate-course.en.md)

这门课程研究三个问题：源语言的语义如何进入中间表示，优化在什么条件下保持语义，以及多层表示如何支持领域优化。学生从没有 LLVM 工程经验开始，在一学期内完成可运行的编译器核心，并围绕一项变换或 lowering 策略完成小型研究项目。

本教案采用 16 周制，每周两次 90 分钟讨论课、一次 60 分钟实验诊所，课外预计 8–12 小时。建议 2 人一组；个人项目缩减工作负载数量，不降低正确性要求。学生应已学过 C++、数据结构、基础编译原理与计算机体系结构。它不是 C++ 或词法分析的入门课。

## 课程范围

必修内容包括 LLVM IR、SSA、数据流分析、Pass 工程、源语言 lowering、优化正确性、实验方法，以及 MLIR 的 operation、region、conversion 和 CPU bufferization。所有学生完成 MLIR 公共实验；自定义 dialect、Transform 调度、GPU 和更复杂的 JIT 系统按项目方向深化。

为给优化与 MLIR 留出时间，统一验收采用 [MiniLang Scalar 核心](language-profile.md)：整数、布尔值、函数、词法作用域、可变绑定、条件与循环。数组、字符串、闭包和完整调试信息不再是所有小组同时必须完成的功能。选择它们的项目必须先提交语义增补，不能沿用尚未定义的 runtime helper。这个范围调整不意味着可以省略诊断、测试或运行时错误。

章节编号仍表示知识目录，不等于教学周。第 00–10 章在前半学期穿插讲授，第 11、14–18 章构成后半学期的优化与多层 IR 主线。讲义、作业和参考实现的实际状态见[发布验收](release-readiness.md)。

## 可观察的学习成果

| 编号 | 学生应独立完成的任务 | 验收证据 |
|---|---|---|
| O1 | 为带分支和循环的函数构造合法 SSA，并解释支配关系 | L1 IR、phi 说明与反例 |
| O2 | 写出优化的前置条件，处理 flags、副作用和分析失效 | L2 正确性说明、不得变换样例 |
| O3 | 将语言规则实现为前端与后端契约 | L3/L4 诊断、运行、ABI 测试 |
| O4 | 设计分阶段 MLIR lowering 并定位转换失败 | L5 中间 IR 与 legality 说明 |
| O5 | 区分性能变化、测量噪声与语义错误 | 原始数据、基线、消融和限制 |
| O6 | 让其他人从干净环境重现结论并回答技术质询 | 复现实验与个人答辩 |

## 十六周安排

下表中的“离课检查”不计独立分数，用来决定下一次课是否需要补讲。作业的具体契约见[作业说明](assignments.md)。

| 周 | 课堂问题与阅读 | 实验和离课检查 | 截止事项 |
|---:|---|---|---|
| 1 | 编译阶段与可观察行为；章 00–01 | L0 环境；说明 verifier 不能证明什么 | 环境记录 |
| 2 | SSA、支配和循环；章 02 | 手算 diamond/loop phi；解释边的语义 | L1 |
| 3 | C++ API、所有权、Pass Manager；章 03–04 | API 生成器与计数 Pass；解释 `all()`/`none()` | L2 开始 |
| 4 | 数据流定点与局部优化合法性；章 04、11 | 用反例击穿一个不安全规则 | L2 |
| 5 | 语言契约与前端接口；章 05–07 | 源码位置、恢复、符号表；论文讨论 1 | L3 开始 |
| 6 | 类型检查与可达返回；章 07–08 | 前端验收；项目问题与可测假设评审 | L3、M1 提案 |
| 7 | CFG lowering、内存与 ABI；章 08–09 | 短路/trap、调用顺序；解释一个错误 GEP | L4 开始 |
| 8 | JIT/AOT 与工程诊断；章 10、12 | 完成一种可靠执行路径；不能以 lli 代称自写 ORC JIT | L4 |
| 9 | 循环优化、别名、poison；章 11 | 正确性优先的基线；论文讨论 2 | M2 可执行基线 |
| 10 | MLIR region 与 dialect；章 14、16 | L5 SCF → CF → LLVM；逐层比较信息 | L5 开始 |
| 11 | Conversion 与 bufferization；章 15–17 | 保留 tensor 旧值的反例；论文讨论 3 | L5 |
| 12 | 自定义 dialect 或优化分析专题 | 中期演示、互换机器复现、失败案例诊所 | M3 中期结果 |
| 13 | Transform 调度与实验设计；章 18 | 参数空间、消融；论文讨论 4 | 评估计划冻结 |
| 14 | 研究实验与结果解释 | 助教审查原始数据；复现实验，不新增核心功能 | 报告草稿 |
| 15 | 成品审查与个人技术答辩 | 干净构建、负例、局限、跨模块讲解 | 代码冻结 |

第 6 周后不扩张共同语言核心。第 9 周仍没有可运行基线的小组暂停新功能，以最小程序贯通前后端；教师缩减实验问题，而不是在最后两周接管学生实现。

## 每次课怎样组织

90 分钟讨论课通常以一个可证伪的问题开始：例如“同样返回 0 的两个函数能否互换”。先给学生 5 分钟写判断，再用 15 分钟对比反例；接着讲解支持判断的定义，用 25 分钟共同推导 IR 或分析结果，最后用 20 分钟阅读真实实现，留下 10 分钟独立作答。其余时间用于澄清和换题，而不是增加新名词。

第二次课以实验结果为材料。学生携带一个最小失败样例，先说输入和预期，再定位失败阶段。教师不要直接替学生修改 IR；先问“哪条语言规则或 verifier 不变量被破坏”。答不出来时回到语义，不继续尝试 Pass 顺序。

实验诊所用来处理环境和集成问题，不替代课堂讨论。助教记录问题类型、复现命令和解决时间。如果同一环境问题影响三个以上小组，应修复公共脚本并发布勘误，而不是让每个小组单独排错。

## 课堂问题与教师参考答案

这些题目用于形成性评价；正式作业采用同一概念的不同输入。

| 周 | 问题 | 教师应听到的关键点 |
|---:|---|---|
| 1 | `opt -passes=verify` 成功是否表示源程序语义正确 | 只检查 IR 结构/类型等不变量，不比较源语言语义 |
| 2 | phi 的 use 属于 merge block 还是前驱边 | incoming value 与对应边关联；支配检查不能按普通指令处理 |
| 3 | 为什么不能在 Context 销毁后保留 Module 中的 Value | LLVM 对象依赖 Context 中的类型等资源，引用生命周期不独立 |
| 4 | 修改指令但保留 CFG，能否返回 `PreservedAnalyses::all()` | 不能据 CFG 未变推断全部分析有效；应精确声明或保守失效 |
| 5 | `-2147483648` 的 lexer 是否应先拒绝正数部分 | 不应过早截断；词法幅值与一元负号语义检查分离 |
| 6 | `if` 一支 return，另一支产生值，该如何合流 | return 分支没有可达合流边；不能给不存在的边添加 phi incoming |
| 7 | `false && trap_call()` 能否先求值两边再 select | 不能；陷阱和副作用使求值顺序可观察 |
| 8 | 外部 `lli` 成功是否证明自己实现了 ORC JIT | 没有；只是运行生成 IR，需明确系统边界 |
| 9 | 可以将带潜在除零的表达式移到 if 外吗 | 需要证明推测执行安全；原来不执行的路径可能新增错误行为 |
| 10 | LLVM dialect 是否就是 LLVM IR 文件 | 不是；还需要翻译，并检查最终目标 IR |
| 11 | tensor 值更新后旧值仍被读取，可否原地写入同一 buffer | 需要别名/读写冲突分析，可能必须复制；bufferization 不自动等于生命周期管理 |
| 12 | verifier 接受一个自定义 op，是否说明它可 lower | 不说明；合法语法、语义验证和 conversion target 是不同契约 |
| 13 | tile size 最快的一次结果是否足以选最佳策略 | 不足；需要重复、顺序控制、工作负载变化和正确性检查 |
| 14 | 几何平均 1.1× 是否说明每个工作负载更快 | 不说明；必须报告逐项结果与退化案例 |
| 15 | 隐藏测试失败是否可以新增一条秘密语言规则 | 不可以；隐藏输入不能隐藏规范 |
| 16 | 没有性能提升的项目能否获得高分 | 可以，若问题合理、实现正确、评估严谨且结论与证据一致 |

## 阅读讨论

每组轮流主持讨论，其他学生提交不超过一页的 reading memo：指出一个技术主张、重述其假设、设计一个可能推翻它的实验。不要只复述摘要。四次讨论分别围绕 LLVM 语义、优化验证、多层 IR 和张量内存化；阅读量控制在一次核心材料加一段实现，不要求通读整个项目文档。

- LLVM 语义：[LLVM 22.1 LangRef](https://releases.llvm.org/22.1.0/docs/LangRef.html)，聚焦 `phi`、`sdiv`、`nsw` 和 poison。
- 优化验证：[Alive2 论文与作者材料](https://web.ist.utl.pt/nuno.lopes/pubs.php?id=alive2-pldi21)，讨论验证范围、循环限制和测试的互补作用；不要求第一次实验就配置求解器。
- 多层 IR：[MLIR 论文](https://arxiv.org/abs/2002.11054)，将论文中的动机对应到一次实际 lowering 的信息损失。
- 内存化：[One-Shot Bufferization](https://mlir.llvm.org/docs/Bufferization/)，解释旧 tensor 值仍存活时为何需要复制，并区分分配与释放。

## 研究项目的边界

所有小组使用相同的可执行语言核心，研究增量只回答一个问题。LLVM 方向可研究局部值编号、循环不变量外提的安全子集、范围分析辅助检查消除或 Pass 排序。MLIR 方向可研究一个领域 operation 的语义验证、两种 lowering 策略、bufferization 的复制行为或两套 Transform schedule。项目必须有无该变换的基线，不能把已有标准优化的效果全部算作自己的贡献。

M1 提案写清问题、假设、最小实现、基线和失败时仍可完成的工作。M2 提供可执行基线及至少一个不得变换的例子。M3 交初步正确性结果、原始测量数据和缩减后的计划。M4 交最终代码、复现步骤、报告和个人贡献说明。具体格式见[研究报告模板](project-report.md)，评分见[评分标准](assessment.md)。

## 教师开课前的责任

学生不应替教师完成发行验证。教师须先在干净镜像上跑全部指定实验，确认参考实现、公开测试和评分脚本针对同一接口。公开仓库中的参考代码无法事后变成秘密；选择公开参考教学时，应要求新的语义变体、测试与解释，而不是声称学生看不到答案。

未完成的实验资产不能列为已准备的必交作业。当前发布状态、阻断项与可先试讲的单元列在[发布验收](release-readiness.md)。讲义完整、代码完整和经过一轮试教是三种不同的成熟度。
