# MiniLang Scalar 教学契约

[简体中文](language-profile.md) | [English](language-profile.en.md)

研究生课程的共同验收范围称为 MiniLang Scalar 1.0。本契约优先于旧版综合语言规范中尚未闭合的数组与字符串要求；未在此列出的聚合类型属于单独批准的项目扩展。这样每个小组能对同一套标量语义比较优化和后端，不必同时实现一门不断扩张的语言。

## 语法与值

沿用[语言规范](language-spec.md)中的函数、参数、声明、块、表达式、`if`、`while` 与 `return` 语法，但 `type` 仅为 `i32 | bool | unit`，不接受数组类型、索引和字符串。`unit` 仅用作函数返回值或不产生值的表达式，禁止作为参数、局部变量类型和可存储值。函数不是一等值，调用目标必须是未被局部绑定遮蔽的顶层函数名。

`+ - *` 和一元负号按模 2³² 运算，再解释为有符号 i32。普通十进制字面量取值 0…2147483647；唯一的额外形式是直接写出的 `-2147483648`，不能先将其正数部分转换为有符号宿主整数。`2147483648`、更大字面量和前导零形式 `01` 均拒绝。lexer 保留幅值或文本，范围检查在一元表达式构造时完成；不能用宿主语言整数溢出作为诊断机制。

除法向零截断，余数符号随被除数。`INT_MIN / -1` 定义为 `INT_MIN`，`INT_MIN % -1` 定义为 0；实现必须在进入 LLVM `sdiv/srem` 前处理这一对操作数，不能直接生成具有未定义行为的运算。除数为零产生 T1。比较使用有符号序，逻辑运算仅接收 bool。

## 作用域与控制流

参数与函数最外层块处于同一个作用域；重复参数、局部变量与参数同名均为 E2002。内层块允许遮蔽，初始化表达式先在旧环境中检查，之后才引入新绑定。`let` 与参数不可赋值，`var` 可以赋值。顶层函数和内置函数不可重定义；局部变量可遮蔽函数名，但不能再把该局部值当作函数调用。

赋值表达式的类型为 unit。所有参数与二元操作数从左到右求值；`&&`、`||` 与 `if` 保持短路。只有 bool 可以作条件。`while` 的类型为 unit。

分析返回路径时，用“是否可达”独立于表达式类型记录控制流。一个无分号尾表达式相当于正常离开函数时的返回值；显式 `return` 没有到后续语句的控制流边。如果 if 的某个分支不正常结束，不要求它为合流贡献值；两个分支都正常结束时类型必须相同。无 else 的 if 只允许正常结束的 then 分支产生 unit。

非 unit 函数的每条可达正常结束路径都必须提供结果；保守地认为 while 可能执行零次，不要求证明无限循环。不可达语句仍进行名字和类型检查，但不生成无前驱的伪合流边。核心没有 `break`、`continue`、异常或隐式转换。

## 输出与运行时接口

| 源语言调用 | 可观察行为 | LLVM/C 边界 |
|---|---|---|
| `print_i32(i32) -> unit` | 十进制有符号整数及一个 LF | `void ml_print_i32(int32_t)` |
| `print_bool(bool) -> unit` | `true` 或 `false` 及一个 LF | `void ml_print_bool(int32_t)`，参数必须为 0/1 |
| `trap(i32) -> unit` | stderr 为 `trap N` 加 LF，立即退出 70 | `void ml_trap(int32_t)`，不返回 |

除零/余零调用 `ml_trap(1)`。不得依赖 SIGFPE、SIGILL 或操作系统信号编号来完成语言级 trap。布尔值在 IR 内使用 i1，跨 runtime 边界显式零扩展为 i32。unit 函数使用 LLVM `void`。目标布局来自目标配置，不从样例复制。小型 C runtime 可以共享，但普通源语言调用不能绕过类型检查。

`main` 必须是无参数的 `fn main() -> i32`。端到端进程退出状态取返回值的低 8 位；测试任意 i32 值时通过 `print_i32` 比较完整数值，而不是把退出码当作完整返回值。优化不得改变 stdout、stderr、正常退出或 trap。

## CLI 与诊断接口

必做 CLI：`minilang check file.ml`、`minilang emit-ir file.ml -o file.ll`、`minilang run file.ml`。`run` 可以调用外部 lli，但报告必须说明它不是自写 ORC JIT；AOT `build` 或嵌入式 ORC 作为项目扩展。成功检查/生成退出 0，源程序错误退出 1，CLI 用法错误退出 2，语言 trap 退出 70。生成失败不得留下看似成功的新输出文件。

错误输出统一为 `path:line:column: error Edddd: message`，位置按 UTF-8 字节计数，从 1 开始，span 为源文件的半开字节区间。CRLF 算一个换行；Tab 算一个字节列，不按显示宽度展开。测试断言编号和位置，不固定中英文 message 全文。第一条错误必须稳定；恢复时不能重复消费同一个 token 而死循环。

沿用 E0001/E1001/E2001–E2003/E3001–E3004；新增 E0002 表示整数范围或形式错误，E3005 表示调用非函数，E4001 表示缺失或签名错误的 main。`check` 与 `emit-ir` 允许库式源码没有 main；`run`/`build` 必须检查入口。核心规范的语义错误优先于任何后端生成。

公开位置断言采用以下锚点：E0001 指向非法字符，E2001 指向未定义标识符的首字节，E2003 指向赋值左侧标识符，E3004 指向条件表达式的首字节。其余诊断也须有有效源码位置，但当前公开驱动不固定其精确列号；增加隐藏位置测试前必须公开对应锚点规则。

## 合法性依据与变更规则

这些行为是课程语言设计，不是 LLVM 默认保证。[LLVM 22.1 LangRef](https://releases.llvm.org/22.1.0/docs/LangRef.html) 是生成 IR 的依据，特别注意有符号除法、poison 与 overflow flags 的差异。第 6 周冻结本契约；之后勘误必须附可执行样例，同时更新中英文、测试和评分说明。新增语法不能混入隐藏测试。
